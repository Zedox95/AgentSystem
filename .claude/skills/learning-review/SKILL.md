---
name: learning-review
description: Improve a repeated workflow after measured successes, recurring failures or explicit user feedback; compare changes against fixed representative tasks before adoption.
---

Read relevant experience entries and their environment fingerprints. Separate user preferences, demonstrated successful methods and unverified hypotheses. Look for one concrete improvement with an observable expected benefit.

Use the existing skill-candidate pipeline to create a proposal from repeated experience. Test outcome quality, evidence correctness, unnecessary tool calls and execution effort against an unchanged baseline. Keep a small representative task set and include a failure case. Never lower acceptance criteria or mark the test result based solely on another model's agreement.

A proposal is not an activated skill. Adoption follows the change contract, backup, objective checks and independent verification; protected policy changes require the applicable approval. Keep the known-good version if results worsen. No paid API or background-model fallback is introduced. Do not create a separate learning agent for every answer.
